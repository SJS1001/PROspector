## 1. The Problem — Siloed data is costing uptime, recovery and throughput

The data required to run a processing plant well already exists; it is simply trapped. Critical signals sit inside OEM systems and vendor portals, so failures surface late and decisions run hours behind the process. The binding constraint is not sensing. It is access and decision latency.

- **Siloed ownership** — Signals locked inside OEM systems and vendor portals. Failures surface late.
- **Lagging decisions** — Spreadsheets and shift reports run hours behind. Recovery drifts uncorrected.
- **Ramp-up gaps** — Capacity gaps during ramp-up erode margin every shift they go unseen.

## 2. The Shift — From dashboards that describe to a decision layer that acts

Historians store the data and dashboards display it; neither closes the loop. ONE adds the missing layer that turns description into action. Put plainly: historians store and dashboards show; ONE decides and drives the work.

2. **Harmonize** — Into one model.
3. **Decide** — Rules, analytics, simulation.
4. **Execute** — Into tasks and alerts.
5. **Learn** — Improve each loop.

## 3. The Operating Model — One operating model for assets and processes

ONE presents a single operating view that managers and operators share. Five modules each answer one question, and together they feed one decision.

1. **Asset health** — what each asset can safely do right now.
2. **Zones** — where a decision applies across the plant.
3. **Work** — what is already being done about it.
4. **Schedule** — what it costs in planned capacity.
5. **Intelligence** — what ONE recommends, and why.
