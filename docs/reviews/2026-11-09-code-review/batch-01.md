# Batch 1: operator: bind the stored AI key to its provider, harden the custom base URL, and stop silent search fallbacks

Severity: medium. App: operator. Base branch: `claude/research-uses-configured-llm`.

Files: `operator/src/lib/server/llm.ts`, `operator/src/lib/domain/openrouter-policy.ts`, `operator/src/lib/domain/openrouter-policy.test.ts`, `operator/src/lib/server/secrets.ts`, `operator/src/lib/server/retrieve.ts`, `operator/src/lib/server/retrieve.test.ts`, `operator/scripts/llm-workspace.test.mjs`, `operator/src/lib/server/research.test.ts`, `operator/src/components/settings-view.tsx`

Findings: Stored AI key is silently reused after a provider switch and sent to another vendor or a custom host; Switching AI provider without a new key sends the previous provider's stored key to the new provider; Stored AI key is not bound to its provider; switching provider sends the old key to the new provider or a custom host, and no test catches it; Custom-provider base URL guard accepts loopback, private and DNS-to-private hosts, and the request follows redirects; Search-mode failures retry silently without web search, billing twice and breaking the no-silent-failover promise; LLM search fallbacks silently send a second paid request on any error, including the 45 s timeout, and drop live search; no test covers these branches; Research test asserts on fns.ts source text, and its title's claim is false at runtime

## Brief

Repo: PROspector. Work only in operator/. Base branch: claude/research-uses-configured-llm. Before editing, read AGENTS.md and the root COMPLETION_LEDGER.md.

GOAL: one PR that (1) stops a stored AI key from being sent to any provider other than the one it was saved for, (2) makes the custom-provider base-URL guard actually reject loopback/private targets and stops following redirects, and (3) stops completeJson from silently retrying a failed web-search call as a second, search-free billed call. It also replaces a source-text test with a behaviour test.

FINDING 1 (medium, secret leakage; three duplicate reports). operator/src/lib/server/llm.ts:45-48 resolveLlmConfig does `key = providerAllowsStoredKeyFallback(spec.id) ? storedKey || getSecret('xai') || process.env.XAI_API_KEY || '' : storedKey`. providerAllowsStoredKeyFallback (operator/src/lib/domain/openrouter-policy.ts:207-209) is true for every provider except openrouter. planConnectionWrites (openrouter-policy.ts:167-199) always writes llm_provider, llm_base_url and llm_model, but writes llm_key only when a key is typed; for non-OpenRouter providers it writes the key into both llm_key and xai (:189-192). settings-view.tsx:343-358 lets the owner save a provider change with an empty key field, and connectionFlags (secrets.ts:74-76) then reports llm=true ('Connected'). Failure scenarios: (a) Anthropic or OpenAI key saved, owner switches to 'custom' https://my-proxy.example/v1 (or groq/mistral/openrouter) without typing a key, and the next completeJson POSTs `Authorization: Bearer <old key>` to the new host (llm.ts:109-111). (b) xai->openrouter sends the xAI key to OpenRouter as storedKey. (c) On a fresh install with XAI_API_KEY in the environment, that key goes to whichever non-xai provider is selected, including a custom host. Existing tests encode the hole: openrouter-policy.test.ts:132-133 asserts an empty-key switch writes only llm_provider, and scripts/llm-workspace.test.mjs:66-68 switches to groq while llm_key holds the Anthropic key, but checks only that the anthropic-workspace-id header is absent.
Required fix: bind the stored key to the provider id and, for custom, to the base-URL origin it was saved for. Store a non-secret marker (for example a secret/setting row llm_key_provider plus llm_key_origin) written by planConnectionWrites in the same write set as llm_key. In resolveLlmConfig, if the marker is missing or differs from the selected provider/origin, refuse with a clear error ('Paste an API key for <provider>') and make no request. Allow the xai secret and XAI_API_KEY fallback only when spec.id === 'xai' (for custom, never). In planConnectionWrites, when llm_provider or llm_base_url changes and no new key is supplied, either clear llm_key (and the xai copy when its provider was not xai) or return a validation error. Choose one and document it in the PR; failing closed (no key sent) is mandatory. connectionFlags must report llm=false when the stored key is not bound to the current provider/origin, so the badge does not say Connected. In settings-view.tsx, show the server error (or block Save) when the provider or base URL changed and the key field is empty. Do NOT edit operator/src/lib/server/fns.ts (another batch owns it). Implement through planConnectionWrites, secrets.ts and llm.ts. If saveConnections in fns.ts must change, stop and record a blocker in COMPLETION_LEDGER.md instead.
Legacy rows: an existing llm_key with no marker should be treated as bound only to the currently saved provider at migration/first read (or treated as unbound, which forces re-entry). Pick the fail-closed option and explain it.

FINDING 2 (low, SSRF). assertPublicHttps in operator/src/lib/server/retrieve.ts:37-58 is string-only. new URL('https://[::1]/').hostname is '[::1]' and net.isIP('[::1]') is 0, so IPv6 literals skip isBlockedIp. Trailing-dot names ('localhost.') and DNS names that resolve to private addresses (127.0.0.1.nip.io) also pass. llm.ts:50-53 validates the custom base URL with assertPublicHttps only (never resolvePublic), and postJson (llm.ts:66-72) uses fetch's default redirect:'follow'. A probe accepted https://[::1]/v1, https://[::ffff:127.0.0.1]/v1, https://localhost./v1, https://127.0.0.1.nip.io/v1 and https://[fd00::1]/v1. The UI hint in operator/src/lib/domain/llm.ts:103 says 'Private hosts are rejected.' (do not change that text; make it true).
Required fix: in assertPublicHttps, strip IPv6 brackets and trailing dots before the IP/hostname checks, so bracketed IPv6 literals hit isBlockedIp. Before each custom-provider request, resolve the host with the existing resolvePublic and reject private answers. Pass redirect:'error' (or 'manual' and refuse) in postJson. Pinning the resolved address with a custom dispatcher is optional; if you skip it, note the remaining DNS-rebinding window in the PR.

FINDING 3 (low, silent failover plus double billing; two duplicate reports). llm.ts:146-151 (xai, `catch { // fall through to chat }`), :167-170 (openai) and :173-178 (openrouter, which retries without plugins:[{id:'web'}]) catch every error from the web-search request. That includes AbortSignal.timeout(45_000) at :70, 401, 429 and 5xx. They then send a second billed chatCompletions request whose prompt still says 'Use live web search'. This contradicts anthropic-search.ts:1 ('never downgrade a failed search to model memory'), seed.ts:312 ('No silent failover') and docs/DIRECTION.md:102.
Required fix: fall back only on a recognised 'tool/endpoint unsupported' response (for example a 400/404 whose body matches a narrow, documented pattern). Never fall back on timeout, auth errors, 429 or 5xx; surface those errors. When a fallback does happen, rebuild the prompt with the existing no-search wording rather than 'Use live web search', and expose the downgrade to the caller (for example a returned flag) so run progress can record it. Do not edit fns.ts or hunt.ts to consume the flag; returning it is enough for this PR.

FINDING 4 (low, test quality). operator/src/lib/server/research.test.ts:33-41 slices fns.ts source and regex-checks it for XAI_API_KEY/api.x.ai. Replace it with a behaviour test against resolveLlmConfig/completeJson. Stub fetch and the secret reads, configure provider X with no bound key, set process.env.XAI_API_KEY, and assert completeJson rejects and fetch is never called (or, with a bound key, every request goes only to provider X's origin). Name the test after what it checks.
