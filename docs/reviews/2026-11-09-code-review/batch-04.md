FINDING 1 (medium, safety-gate bypass; latent because production uses the reject-only materializer). prospect-review.ts:52 `const materialSignal=signalRows.results.filter(x=>Boolean(x.material))...[0]`, and :56-60 reentryKind gives 'material_signal' to a rejected prospect, or to a deferred prospect before reviewAt, whenever any signal in the current submission has material=1. material is a pure kind check (source-policy.ts:14). Nothing requires the signal to be retrieved and observed after priorInactive.decision_at, or to differ from the evidence the owner rejected. The sourced-disproof path already does this (source-policy.ts appendSourcedDisproofValidationMarker requires occurred_at and retrieved_at > decision_at). CONTEXT.md defines a Material Signal as 'A new Signal' and says republication or repetition is not material. Signals are stored per submission with no cross-submission dedupe (source-policy.ts:44). Reachable path (verified by reading the code): the owner rejects prospect P whose assessment cites material event E. The owner then replaces the Profile configuration, and activation creates a new initial run with window_lower_exclusive NULL (profile-readiness.ts:179). The runner re-reports the exact pre-decision event E, which yields a new candidate (new configuration_id). persistQualificationAssessment then writes a 'material_signal' prospect_reentry_event and a new active qualified prospect during the 90-day cooldown. The same applies to Defer before reviewAt. (A plain overlapping scheduled run under the same configuration does NOT reopen it, because materializeCandidate reuses the candidate and the digest short-circuits at :51.)
Required fix: a signal counts as a re-entry Material Signal only if (a) both its occurred/observed time and its retrieved_at are strictly after priorInactive.decision_at, and (b) its observation identity (fingerprint, or kind plus underlying origin plus occurredAt, matching how source-policy identifies observations) does not appear in the prior assessment's evidence_json, or in any earlier submission's signals for the same workspace/profile/prospect target. If no signal qualifies, keep the existing refusal path ('cooldown remains active' / 'Material Signal is required for re-entry'), so the gate stays fail-closed. Do not change the sourced-disproof path.

FINDING 2 (low, fail-open; plausible). rubricDigest() at prospect-review.ts:198 returns "0".repeat(64) on every fallback: no top-level manifest rubricDigest, and confirmedCategoryInputs.rubric missing or not exactly one entry. qualification.ts:122 digest() is regex-only, so the sentinel is 'valid' and the immutable_configuration gate passes (qualification.ts:72-74).
