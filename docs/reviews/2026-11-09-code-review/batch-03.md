# Batch 3: operator: recover interrupted runs, claim runs atomically, and make do-not-contact and merge suppressions actually match

Severity: medium. App: operator. Base branch: `claude/research-uses-configured-llm`.

Files: `operator/src/lib/server/fns.ts`, `operator/src/lib/server/archive.ts`, `operator/server/local-node-entry.ts`, `operator/src/lib/server/hunt.ts`, `operator/migrations`, `operator/src/components/outreach-view.tsx`, `operator/scripts/manual-workflow-actions.test.mjs`, `operator/scripts/manual-workflow.test.mjs`, `operator/scripts/archive-regression.test.mjs`

Findings: An orphaned 'running' run permanently blocks all future hunts or discoveries; Do-not-contact entries are not normalized or validated, so many silently never match; Merging contacts discards contact-level suppression, so an opted-out mailbox becomes eligible again; Concurrent run starts race the busy check; the duplicate run bills AI and then loses all its results

## Brief

Repo: PROspector. Work only in operator/. Base branch: claude/research-uses-configured-llm. Before editing, read AGENTS.md and the root COMPLETION_LEDGER.md.

GOAL: one PR that removes a permanent run lockout, makes run start atomic, and closes two do-not-contact gaps. This batch owns operator/src/lib/server/fns.ts. No other batch in this round edits it.

FINDING 1 (medium, availability). startHunt (fns.ts:902-907) and runDiscovery (fns.ts:1226, 1258-1260) refuse whenever any prospecting_runs or discovery_runs row is 'queued' or 'running'. A run reaches a terminal status only inside the same request (executeHunt/discover at hunt.ts:283 and discover.ts:65, or the catch blocks at fns.ts:964, 1239, 1273). Nothing at startup, no stale lease and no cancel recovers an interrupted run. server/local-shutdown.mjs force-closes sockets after 5s, and anthropicSearch alone allows 180s. archive.ts:251-252 accepts and restores 'queued'/'running' rows unchanged. Failure: quit the app (or sleep/kill the process) mid-hunt; on relaunch every 'Find prospects' click says 'A prospecting run is already active' forever, while the UI polls every 1.5s (workspace.ts:45). The same happens after restoring a backup taken mid-run.
Required fix: at server start (operator/server/local-node-entry.ts, before serving requests and after migrations), in one statement per table, mark every queued/running prospecting_runs and discovery_runs row failed with terminal_reason 'Interrupted; not resumed'. Do the same in archive restore: normalise restored run status to 'failed' with the same reason in transform() or the restore path in archive.ts. Do not add an age-based staleness heuristic unless you also keep the startup sweep.
Tests first: in scripts/archive-regression.test.mjs (or a new scripts/*.test.mjs using the existing PGlite fixture pattern), seed a 'running' run, run the startup recovery function, and assert the row is failed with that reason and that startHunt/runDiscovery no longer refuse. Restoring an archive containing 'running'/'queued' runs yields failed rows. Export the recovery as a function so it is testable without starting the server.

FINDING 2 (low, race; plausible). Between the busy select (fns.ts:902), the throttle select (909-916; the 'initial' trigger skips it), the profile upsert and the run insert (931-938) there are awaits and no unique partial index (migrations/0003 index is non-unique). hunt.ts:246-259 inserts prospects with deterministic ids idFor(user, hunt:fingerprint) and no ON CONFLICT. Two overlapping starts (two tabs or direct calls) both run and both spend. The second final transaction then fails on the primary key, and that run is marked failed, losing its other accepted results. runDiscovery has the same pattern (fns.ts:1258-1267).
Required fix: claim the run atomically. Use `insert ... select ... where not exists (select 1 from prospecting_runs where user_id=$1 and status in ('queued','running')) returning id`, refusing when no row returns, or add a new migration with a unique partial index on (user_id) where status in ('queued','running') per table and catch the violation as 'already active'. Apply the same to discovery_runs. Make the hunt's prospect and signal inserts `on conflict do nothing` (hunt.ts). If you add a migration, it must be a new numbered file in operator/migrations (next after 0009_search_progress.sql). Follow the conventions checked by scripts/migration-plan.test.mjs and scripts/local-database.test.mjs, and never edit an existing migration. The startup sweep from Finding 1 must run before the index can be relied on.
Tests first: two concurrent startHunt-equivalent claims (Promise.all against the PGlite fixture) produce exactly one run row and one 'already active' refusal. A hunt commit that re-inserts an existing prospect id does not throw.

FINDING 3 (medium, safety gate). addSuppression (fns.ts:1411-1427) only applies NFC, trim and lowercase. Matching (manual-workflow.ts:12-19) is exact: domain equals split_part(email,'@',2), org equals account_name, contact equals contact id. The UI (outreach-view.tsx:427-450) labels every non-domain kind 'Email' with an email placeholder and promises 'Blocks outreach even if previously approved'. Failure: kind=Domain value '@acme.com', 'https://acme.com' or 'www.acme.com' is saved and listed, while Draft/Approve/CSV still include acme.com contacts.
Required fix: normalise per kind in addSuppression. For domain: strip scheme, path, port, a leading '@' and a leading 'www.', apply IDNA/lowercase, then validate it is a hostname, and reject anything else with a clear error. For email: validate the address shape. For contact: require an existing contact id in the user's workspace. For org: keep exact matching but return a warning when no account_name matches. Reject values that cannot match instead of saving them. In outreach-view.tsx, label and set the placeholder for the value input per kind, and show the server error. Do NOT change the matching predicate in manual-workflow.ts. Subdomain blocking (mail.acme.com under acme.com) is a product decision outside this PR: note it in the PR, do not implement it.
Tests first (scripts/manual-workflow-actions.test.mjs or manual-workflow.test.mjs): adding domain '@acme.com', 'https://www.acme.com/x' or 'www.acme.com' stores 'acme.com' and excludes jane@acme.com from manualCrmCsv and prepare/approve. 'not a domain' is rejected. An unknown contact id is rejected. A malformed email is rejected.

FINDING 4 (low, safety gate; latent because no UI calls useMergeContacts). mergeContacts (fns.ts:1576-1601, delete at ~1594) deletes the dropped contact and inserts identity_merges without moving its 'contact' suppression.
