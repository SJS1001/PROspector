FINDING 1 (medium, safety gate). site/domain/manual-call-decision-service.ts recordOutcome (lines ~231-235) re-runs the full call-eligibility evaluate() for every outcome, including do_not_call. It throws manual_call_decision:stale_or_ineligible unless decision.eligible is true and the decision digest equals the one from decide(). The do-not-call suppression and pending-work cancellation (doNotCallRequirements, ~263-267) are only sent to commitCurrentOutcome after that gate. Failure scenario: decide() at T, the approval expires at T+10s (expiresAt = NOW+10_000), and the owner records do_not_call at T+10.001s. evaluate() adds approval_expired and the call throws, so no suppression tombstone is written, no matching pending email work is cancelled and no outcome is recorded. The same happens when phone freshUntil passes, the eligibility snapshot is re-projected, another pending work item appears (changing the authority digest), or the authority revision bumps. Because decide() can never return eligible again after expiry, the stop signal cannot be recorded at all. A probe built from the test file's fixtures printed `DNC rejected: manual_call_decision:stale_or_ineligible suppressed: false commits: 0`. The docs make do-not-call a hard control that always overrides approval: README.md:28, docs/adr/0005, docs/IMPLEMENTATION-SPEC.md:379.
Required fix: when outcome === 'do_not_call', skip the eligibility and decision-digest equality gate. Still require workspace/owner scope, the approval-id and phone-observation binding, and synthetic classification. Always build doNotCallRequirements from the CURRENT authority (suppressionSubjects and matchingPendingWork) and pass them to commitCurrentOutcome. The commit must succeed when the contact is already suppressed (idempotent) or the authority changed since decide(). Record the current reason codes as context on the outcome record. All non-DNC outcomes keep the existing gate unchanged. Do not widen anything else.
Tests first (site/tests/manual-call-decision-service.test.mjs; reuse its fixtures and SyntheticRepositories). DNC recorded after approval expiry writes a suppression, cancels matching pending work and records the outcome. DNC after phone freshness lapses does the same. DNC when the contact is already suppressed succeeds idempotently. DNC after the authority digest changed (extra pending work) uses the current pending work. A non-DNC outcome after expiry still throws stale_or_ineligible (regression guard). DNC with a wrong workspace/owner or a mismatched approval/phone binding still throws.

FINDING 2 (low, correctness). site/domain/crm-handoff-export-artifact.ts evaluate() (~274-293) checks `selected.size === selectedRows.length && rows.length === selected.size` and that each supplied row maps to some selected reference with a matching digest. It never checks that each selected reference is matched exactly once. normalizeRows (~394) does not reject duplicates, and encodeCrmCsv (crm-csv-codec.ts:203-212) silently collapses exact duplicates. For selection {A,B} with supplied rows [A,A], validation returns accepted with rowCount 2, while the artifact has manifest.rowCount 1 and B is absent (probe: `validation.rowCount 2 artifact rowCount 1`, `B present: false`). The module claims an 'exact row set' (~189).
Required fix: track the selected identities already matched and fail with crm_handoff_export_selection_mismatch on a second match for the same identity, so the set of supplied identities must equal the selected key set. In buildCrmHandoffExportArtifact, assert manifest.rowCount === validation.rowCount before returning, and throw or refuse otherwise. Do not change crm-csv-codec.ts.
Tests first (site/tests/crm-handoff-export-artifact.test.mjs, next to the missing/extra-row case at ~174). [A,A] for {A,B} is rejected with crm_handoff_export_selection_mismatch. [A,B,B] is rejected. [B,A] (reordered) is still accepted.
